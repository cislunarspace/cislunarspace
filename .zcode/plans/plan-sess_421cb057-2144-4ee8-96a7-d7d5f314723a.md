# 系统设计：产出两份 ADR 供评审（本次只写设计，不实施）

## 背景结论（调研已完成）

- **结构数据层已治理完毕**：ADR-0001/0002 已把 7 个分散文件统一进 `web/.vuepress/taxonomy/`，带校验器和测试。这次不需要再动它。
- **真正缺失的是"内容操作层"**：三个内容写入者互不相通——space-news 自动管线（Python+bash，每小时）、admin GUI（4052 行，用正则字符串手术改 `taxonomy/data.ts` 源码）、agent/人工直接编辑。admin"麻烦"的根源是没覆盖闭环：不能新建内容、保存后索引不同步。
- **资产层乱源已定位**：生成 JSON 提交进 git（1.1MB glossary sidebar 等）但除管线 `git add` 惯性外无任何消费者；中英图片整目录复制致约 230MB 冗余（`sync-figures` 是图片进 dist 的唯一通道，去重可不动任何 md）；901KB 死产物；孤儿图片；目录六类混杂。
- **glossary 关键新事实**：3075 个词条页面**线上根本不存在**（`pagePatterns` 排除出 SSR、无客户端渲染组件、`dist/glossary/` 为空），但 navbar 入口、sidebar 树、1.1MB 索引产物、翻译缺口机制仍在为它运转。md 的真实现存价值 = AI 问答语料（`ai-chat-context.ts` 全站扫描）。

## 产出物

1. **`docs/adr/0003-content-module.md` — 内容操作模块（Content Module）**
   - 新深模块 `web/.vuepress/content/`：接口为领域操作（`list / read / write / create / delete / pairStatus / categories.add/remove / refreshIndex`），按内容族（space-news / glossary / kb-section）组织；实现封装路径约定、frontmatter 校验、双语配对、README 索引行、figures 约定、回收站、gen-sidebar 触发。
   - 分类管理消灭字符串手术：`newsCategoryNodes` 从 `taxonomy/data.ts` 拆到独立数据文件，写回采用"整文件序列化生成"，永不文本拼接。
   - 消费者迁移路径：admin 后端迁入并补"新建内容 + 保存后索引刷新"两个缺口；管线与 agent 通过 CLI 消费。
   - 接口级行为测试要求。
2. **`docs/adr/0004-asset-layering.md` — 资产分层与仓库形态**
   - 三层模型：内容源（进 git）/ 派生数据（出 git，构建生成）/ 构建产物（dist）。
   - 具体决策：生成物出 git 清单与管线 `git add` 同步改造；双写收敛；死产物删除；图片单一来源方案（zh 侧一份，`sync-figures` 复制到 dist 两个位置，en 侧先 md5 全量校验再删）；孤儿图清理。
   - glossary 二选一（写成开放决策点，评审时拍板）：A. 承认现状定位为"AI 语料库"（摘 navbar 死入口、停 sidebar 产物、保留 AI 扫描）——推荐；B. 复活为客户端渲染词典（单页 + JSON）。
   - 目录归位清单（theme2→theme、scripts/ 六类分流、数据文件归位、patch 脚本纳入 npm scripts）。
   - 双语镜像收紧：月份归档一致性、figures 命名统一、孤儿资源检查纳入 check 族。
3. **两份 ADR 均附分阶段 follow-up 路线图**（速赢→图片→content 模块→glossary→检查收紧），延续 ADR-0001 的 follow-up 模式。
4. **`CONTEXT.md` 增补新词汇**：Content module、内容族等，与既有 Adapter/Intake 词汇衔接。

## 不做什么

- 不动 taxonomy 模块本身；不实施任何清理或代码改动（评审通过后按 follow-up 分批实施）；不修改 admin 代码。

ADR 写作遵循仓库 AGENTS.md 的写作要求（准确、观点鲜明、去废话），格式对齐既有 ADR-0001（Status/Context/Decision/Rules/Consequences/Follow-up/Alternatives）。
