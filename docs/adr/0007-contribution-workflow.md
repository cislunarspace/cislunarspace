# ADR 0007：贡献流程——type/kind/area 标签、五类模板与共用推进面板

**状态**：已接受
**日期**：2026-09-04
**关联**：AGENTS.md「issue / PR / 评论的格式」（本 ADR 不改它的正文结构约定，只补它没覆盖的分类、标签与面板）；CONTRIBUTING.md（对外声明与面板说明）；e2m2e 仓 [ADR 0046](https://github.com/cislunarspace/e2m2e/blob/master/docs/adr/0046-contribution-workflow.md)（同一体系的先行决策）；transfer-orbit-design 仓 [ADR 0029](https://github.com/cislunarspace/transfer-orbit-design/blob/master/docs/adr/0029-contribution-workflow.md)（姊妹决策）；共用面板 cislunarspace/projects/1

## 背景

本仓库已纳入与 e2m2e、transfer-orbit-design 共用的推进面板「cislunarspace Issue Management」（users/cislunarspace/projects/1，板描述已点名三仓）。但仓库侧流程缺位：没有 Issue 与 PR 模板，AGENTS.md 定下的正文结构只约束读得到 AGENTS.md 的人，外部贡献者看不见；标签只有分诊一组（`needs-triage` 等，见 docs/agents/triage-labels.md），没有表达改动意图与影响领域的轴；Issue 推进状态没有承载，翻列表靠记性。

姊妹仓 e2m2e（ADR 0046）与 transfer-orbit-design（ADR 0029）已先后落地同一套体系：五类 Issue 模板、type/kind/area 三组标签、七态 Project 面板。三仓同一维护者，工作经常跨仓成对出现。

## 决策

### 1. 正文结构沿用 AGENTS.md，模板把它焊死

五套 Issue 模板（Bug / Feature / Idea / Research / Task）正文一律 Problem / Proposal / 上下文 三段加待拍板行，PR 模板按 Closes 置顶 + Summary / Motivation / Changes / Why this is safe / Test plan 五段。AGENTS.md 同步补「issue / PR / 评论的格式」一节（提案先行、创建与入板命令、AI 标识、不代改他人内容），模板是该节格式约束的外化，不改写它。

### 2. type/kind/area 三组标签，与姊妹仓同构

- Issue 分类由模板创建时自动打 `type/*`（个人仓库没有组织仓库的原生 Issue Type）；
- PR 恰好一个 `kind/*`（闭集六种，与姊妹仓相同；refactor 并入 kind/cleanup）；
- PR 至少一个 `area/*`（开放集），初版七个按本仓持久领域：content（知识库章节长文与教程）、glossary（术语词典词条）、references（ref.bib 与引用键体系）、web（VuePress 站点、主题与构建管线）、ai-chat（AI 问答表面）、docs（工程文档）、infra（CI、部署与脚本）。

### 3. 纳入共用推进面板

不新开面板，本仓 Issue 直接入「cislunarspace Issue Management」，Repository 字段区分来源。七态流水线（Inbox / Backlog / Ready / In progress / In review / Done / No action）、Priority、Start Date、内置自动化（入板→Inbox、关闭→Done、重开→Inbox、PR 联动）全部沿用。个人账号项目无按仓库自动入板，普通 issue 建成后须 `gh project item-add 1 --owner cislunarspace --url <issue URL>` 手动入板（已写入 AGENTS.md 与 docs/agents/issue-tracker.md）。

### 4. Discussions 开启

使用问题与想法探讨走 Discussions，不占用 Issue；模板选择器页（config.yml）指向它，blank issue 关闭。

### 5. AI 贡献要求声明

三层落位：CONTRIBUTING.md 开头段为对外正式声明（未正确标记 `[AI Generated]` 的不予受理，不开展进一步工作和实施）；AGENTS.md「评论」小节为 agent 操作条款（含评论末尾 generated by AI 标识）；五类 Issue 模板与 PR 模板的 HTML 注释内嵌提示。标记顺序定为 `[AI Generated]` 位于类型标签之前。

## 备选

- **本仓独立一块面板**：与姊妹仓完全对称，但跨仓工作要看三处、内置自动化要再配；单人维护三仓，一屏看全胜过对称。
- **只写 CONTRIBUTING 不加模板**：外部贡献者看不到 AGENTS.md 的结构约定，声明没有承载，正文结构仍靠自觉。
- **不引入 AI 声明**：三仓实践里 AI 产出已是主要来源，无标识则人类审核无从分辨产线，风险不对称。

## 后果

- 新增：CONTRIBUTING.md、五套 Issue 模板与 config.yml、PR 模板、CLAUDE.md 指针（Claude Code 兼容，见 e2m2e 同做法）。
- 变更：AGENTS.md 补「issue / PR / 评论的格式」一节与 commit 标题禁用破折号条款；docs/agents/issue-tracker.md 补手动入板命令；README 贡献节指向 CONTRIBUTING.md。
- GitHub 侧（label 创建、面板条目、Discussions 开关）即时生效，不进 git diff。
- 不变：分诊标签（needs-triage、needs-info、ready-for-agent、ready-for-human，见 docs/agents/triage-labels.md）；AGENTS.md 的写作要求与编码准则。
- 代价：标签与面板状态仍靠维护者手工维护（与姊妹仓相同的取舍）；PR 量增大或规则漂移出现时，再评估 policy 自动化。
