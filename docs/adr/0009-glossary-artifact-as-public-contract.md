# ADR 0009：词典工件作为对外数据契约

- Status: Accepted
- Date: 2026-10-22
- 关联：ADR 0004（资产分层，派生数据不进 git）、issue #77

## Context

站外的 AI 客户端要按关键词取站内词典数据。这类客户端接入外部数据只有一条通用路径：本地或远程的 MCP server，内置 web search 的后端不可配置成自建端点。所以站点能承诺的东西是一份可下载的数据，不是一个查询接口。

站内已有 `public/glossary-dictionary.json`（约 316 KB，8 类 720 条），构建期生成，线上可跨域 GET，同时被站内词典页 `GlossaryDict.vue` 消费。它今天不能直接对外用，有三处缺陷。条目键是裸文件名 slug，14 组跨分类同名条目互相覆盖，实测 `fundamentals/vsi` 与 `dynamics/vsi` 拿到同一段定义。定义正文保留 `\cite{key}` 与 LaTeX 原文，720 条里 594 条含引用标记。条目没有页面路径，客户端只能按目录规则自己拼，而路径真源是词条 frontmatter 的 `permalink`。

## Decision

1. 一个工件承担两种消费。不新增检索专用工件，扩展 `glossary-dictionary.json`，站内词典页与站外客户端读同一份数据，字段只增不改。
2. 条目身份是分类 slug 加词条 slug。同名不同文的条目各自独立保留，不合并。生成器的字典键随之改为 `分类/slug`。
3. 定义正文剥离 `\cite{...}` 与公式，引用键另存为 `citations` 数组，多键引用按逗号拆开。保留键而不是渲染好的引文，因为 `bibliography.json` 能把键映射成题录，渲染留给消费方。
4. 每条目带 `url`，取自词条 frontmatter 的 `permalink`，缺省时按目录规则推导。
5. 检索在客户端完成，站点不提供按关键词取子集的接口。720 条在内存里做分层打分的子串匹配足够，不预生成倒排索引。
6. 可运行的 MCP server 放在仓库外的独立仓库，本仓只负责数据与接入文档。

## Consequences

对外契约只有一份文件，站内呈现与外部字段在同一处改动，不会出现两份数据不同步。

字段只增不改意味着破坏性调整不可做，例如把 `categories` 嵌套改成扁平数组。将来确实要重构时，只能新增字段而不是改旧字段。

客户端检索质量取决于分层子串匹配，错字与同义词召回有限。这一限制被接受，因为模型给出的关键词通常是词条原文。

引用标记剥离后，站内词典页显示的定义也变干净，编辑侧不必再处理渲染。

`citations` 只存键，题录映射交给 `bibliography.json`，两份派生数据之间形成隐式引用关系。`bibliography.json` 缺键时 `citations` 会留下悬空键，需要构建期校验覆盖。

## Alternatives considered

- 站点提供带 query 的接口，形如 `/api/dict?q=近地点`：否决。静态文件做不到，需要常驻 Node 服务与 nginx location，还要限流与鉴权语义，而数据是纯静态只读的。`admin/` 不能复用，它无鉴权且能写内容并执行 npm 命令。
- 站点托管远程 MCP server：否决。要长期进程、OAuth、限流与提示注入防护，对纯静态只读数据不成比例。
- 新增独立检索工件：否决。与现有工件重复约 300 KB 数据，还要保证两份同步，换来的只是外部形状自由一些。
- 在工件里存渲染后的引文文本：否决。题录格式由 `bibliography.json` 统一派生，两处渲染会漂移，工具体积也会明显变大。
- 合并 14 组同名条目：否决。两份定义的侧重不同（功率受限视角与比冲可调视角），合并会丢信息。
- 预生成中文 n-gram 倒排索引：否决。工件体积翻倍，收益只在错字容忍。
